# 物时 · 微信小程序

> 记住物品的保质期，也记住每件事的间隔 —— 食品、药品、化妆品用**倒计时**防过期；床单、牙刷、滤芯等**物品**，以及洗澡、剪指甲、距离上次吃火锅等**事件**，用**正计时**提醒。

## 功能

| 能力 | 说明 |
|---|---|
| 倒计时模式 | 填生产日期 + 保质期（天/月/年），自动算到期日；包装只印到期日时可手动填写 |
| 正计时模式 | 记上次更换/发生日期 + 循环间隔（天），显示已过时长，处理完一键"重新计时" |
| 物品 / 事件 | 正计时下可选记录类型；**物品**是有实体的东西，**事件**是发生在身上的事，各有独立分类与文案，分别显示在底部「物品」和「事件」页 |
| 纯记录事件 | 事件的**循环间隔是可选**的：关掉开关就只记录「距离上次多久」，文案变成「刚刚做完 / 有一阵没做了 / 快忘记了」 |
| 精确到小时 | 不足一天的记录直接显示「5 小时」（不到 1 小时显示「N 分钟」），不再含糊地说「0 天」；超过一天才回到「天」「个月」这样的大刻度 |
| 倒计时分级 | 倒计时剩余不足 30 天直接说天数；30 天以上换成「1个月4天」「1年4个月」，跨度一眼可读 |
| 起点时刻 | 创建或「重新计时」时自动记下精确到分钟的发生时刻，一天之内直接显示「5 小时」，而不是含糊的「0 天」；编辑页可点「↻ 取当前时间」重设 |
| 详细计时 | 打开后把超过一天的部分也拆细，显示「1年2个月3天5小时」这样的细分时长（0 值段不显示） |
| 首页置顶 | 在编辑页打开「置顶到首页」，记录就固定显示在首页最上方，随时看得见；最多可置顶 **5 条**，倒计时与正计时都可以，名额满了会提示 |
| 关注 / 处理列表 | 首页只列出**真的会提醒**的记录：没设循环间隔的事件（纯记录）不会混进「需要关注 / 需要处理」；已置顶的记录也不重复出现；两个分组可在「我的 → 偏好」里分别关掉 |
| 高对比配色 | 状态红黄绿更饱和鲜明，正常绿 / 临近琥珀 / 紧急红 / 已过期灰在暖米底上一眼可辨；不画进度条，紧迫度靠颜色与状态词表达 |
| 字号随状态 | 主数值以复合单位字号为基准（单独天数与「1个月4天」同一字号），状态每递进一档数字再放大一级 —— 颜色之外多一层「大小」提示，不用细看也能感到紧迫度 |
| 分类统计 | 首页概览卡顶部是**问候 + 一句陪伴文案 + 当日日期**；下面分「物品」「事件」两行（横线分隔），组名在左，右边四格「数字在上、名称在下」（充裕/临近/紧急/已过期，事件为 最近/偏久/该做/快忘）；点一下直接跳到对应列表并筛好状态 |
| 预设模板 | 32 个常见物品 + 26 个常见事件一键填充（牛奶 7 天、床单 14 天、牙刷 90 天、吃火锅 30 天…） |
| 管理 | 搜索、分类 tab、状态筛选、排序偏好持久化、长按编辑/删除 |
| 使用记录 | 在「我的」里按日期回看物品的用掉流水，可一键撤销刚做的操作 |
| 事件记录 | 在「我的」里按日期回看每件事每次「重新计时」的时刻，以及**与上次相隔多久** |
| 数据 | 纯本地存储，不登录、不上传服务器 |

## 技术栈

- 微信**原生**小程序（WXML / WXSS / JS），无 npm 依赖
- 数据层 `miniprogram/utils/storage.js` 基于 `wx.setStorageSync`，迁移云开发时只需替换该文件
- 设计语言：新极简 + 舒缓式；主色鲜明草绿 `#0A7F4E`，四档状态色高对比（正常 `#0A7F4E` / 临近 `#D97B00` / 紧急 `#E0341F` / 已过期 `#5F5F57`）

## 运行

1. 微信开发者工具 → 导入项目 → 选择本目录
2. 将 `project.config.json` 中的 `appid` 从 `touristappid` 替换为你的小程序 AppID
3. 点击编译；首次启动会写入 8 条示例数据（含有/无循环间隔两种事件），可在「我的 → 清空所有数据」清除

重新生成 tabBar 图标（修改配色/形状后）：

```bash
python tools/gen_tabbar_icons.py
```

## 数据模型

```js
{
  id, name, icon, category,
  kind,                            // item 物品 | event 事件（事件仅正计时）
  mode,                            // countdown 倒计时 | countup 正计时
  produceDate, shelfLife, shelfLifeUnit, expireDate, expireManual,
  lastDate, cycleDays,                 // cycleDays 为空且 kind=event 时 = 纯记录（不提醒、不进关注/处理列表）
  detailTiming, lastAt,                // lastAt = 起点精确时刻（毫秒，所有正计时都写；0 = 按当天 0 点计）；detailTiming 仅控制是否展示细分
  pinned, pinnedAt,                    // 首页置顶：是否置顶 + 置顶时间（最多 5 条，按置顶先后排序）
  quantity, unit, location, remindDays, remark,
  usageLog: [{ id, t, ts, n, unit }],   // 物品消耗流水（用掉一个 / 撤销），最多 40 条
  eventLog: [{ id, t, ts }],            // 正计时重新计时流水，最多 40 条（事件记录页数据源）
  createdAt, updatedAt
}
```

状态判定（`utils/time.js`，按自然日 UTC 计算）：

- 倒计时：`<0 已过期 / ≤3 紧急 / ≤remindDays 临近 / 其余 充裕`
- 正计时（有循环间隔）：`<0 已超期 / ≤urgentDays 该处理 / ≤soonDays 快到期 / 其余 正常`（物品与事件措辞不同）
  - 阈值随周期缩放：`urgentDays = cycle ≥ 7 ? 3 : floor(cycle × 0.25)`，`soonDays = max(urgentDays, min(remindDays, floor(cycle / 2)))`
- 正计时（纯记录，无循环间隔）：按已过去天数取档位 —— 刚刚做完 / 才做过不久 / 有一阵没做了 / 很久没做了 / 快忘记了（`remindable = false`，不进首页关注/处理列表）

主数值显示（`getItemState`）：

- 展示顺序：**状态文字在前，时间数字在后**（如「剩余 12 天」「已过期 10 天」「已过去 5 天」）
- 倒计时：剩余（或已过期）不足 30 天 → 显示「N 天」；30 天及以上 → 日历法复合单位，如「1个月4天」「1年4个月」
- 正计时：距上次不足 24 小时 → 显示「N 小时」（不足 1 小时 →「N 分钟」）；超过一天 → 显示「N 天」
- 有 `lastAt` 时按真实时长算；没有则从当天 0 点起算（老数据降级口径）
- 分段渲染（v2.2）：`state.mainParts = [{v,u}]`，复合单位也拆成「数字 + 小号单位」多段，与「只有天」的排版格式一致
- 字号档位（v2.3）：`state.mainSize` 为 1~4（充裕→临近→紧急→已过期），单独天数与复合单位共用同一基准（卡片 42rpx / 详情页 76rpx），再按档位放大到 60rpx / 124rpx
- **进度条与进度环已取消**（v2.1）：卡片与详情页都不再画进度，紧迫度由状态色与状态词表达（`state.percent` 仍在计算，仅供扩展）

首页概览统计（v2.3，v2.4 精简）：

- 概览卡顶部（v2.5）：**问候语 + 一句陪伴文案**（语言库随机）+ 当日日期日历；页面顶部不再单独放问候块，「使用说明」入口移到「我的」页
- 顶部排版（v2.6）：问候语 `52rpx` 加粗置于顶，一句话文案沉到区块底部（与日历底齐平），**既远离问候、又贴近下方统计行横线**
- 「物品」组：充裕 / 临近 / 紧急 / 已过期，「事件」组：最近 / 偏久 / 该做 / 快忘（均两个字）
- 两组配色与顺序一致（绿 → 琥珀 → 红 → 灰），定义在 `ITEM_STAT_META` / `EVENT_STAT_META`
- 每行是横线分隔的一行（`.ov-stat`）：**组名在左**，右边四格**数字在上、名称在下**（`.ov-cell-num` 40rpx / `.ov-cell-name` 24rpx）；**不显示条数小计**，没有记录时只显示空态提示
- 格子可点击：物品格跳物品页、事件格跳事件页（`globalData.filterStatus` / `filterEventStatus`）
